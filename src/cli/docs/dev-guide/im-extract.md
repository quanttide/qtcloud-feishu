# 聊天知识提取迁入

## 现状

`extract.rs` 的 `extract_from_text(text, system_prompt)` 读 `DEEPSEEK_API_KEY`，用 quanttide-agent 的 LLM 客户端调 deepseek-chat，要求 JSON 输出，最后解析成结构化值。两个示例把聊天搜索结果拼成带时间与发送人的文本，用固定提示词提取政策，写到 `data/<域>/*.yaml`。

这条链路里只有搜索是飞书的事；提示词、模型调用与输出落盘是领域与 AI 的事。

## 目标

本仓只交付输入侧：搜索动作、原样镜像与行字段契约，见 [聊天记录搜索](im-search.md)。不引入 LLM 依赖，不读 `DEEPSEEK_API_KEY`，不写提示词，不定义提取结果的 schema。

提取逻辑迁到领域仓：qtrecurit 保留招聘政策提示词与输出路径，qtclass 的同类示例归课堂域。它们从适配层的行数据或 `raw/` 镜像取输入，模型调用与输出格式不变。

## 实现方案

### 输入契约

「搜聊天记录」定义给出五列：发送人、内容、时间、message_id 与 chat_id。示例把行拼成 `[时间] 发送人: 内容` 的文本，这个格式由消费侧决定，适配层不提供拼接函数。

需要更多上下文时读 `raw/im/messages-search/<页序>.json`。原样响应里有 mentions、reactions 等被拍平时丢掉的字段，领域侧可以按 message_id 回查。

### 领域侧改动

qtrecurit 与 qtclass 的示例迁出本仓，建议落到各自领域仓的 `examples/` 或工具目录，依赖 `qtcloud-feishu-cli` 作为库，用一个薄封装调用定义或 `pull`。提示词、输出路径与 YAML 序列化保持原样，测试用固定输入与假模型，不联网。

领域仓不想依赖 Rust 库时，也可以只读镜像目录：`raw/im/messages-search/` 加 `cursor/`，用任意语言解析。这是最低耦合的备选。

### 隐私边界

聊天原文进入镜像是适配层的既定行为，目录权限按 XDG 数据目录管理。把原文发给外部模型属于数据出域，由领域侧在提示词与流程上做脱敏与授权。适配层不做隐式过滤，也不默认上传。

## 迁移步骤

1. 先完成 [聊天记录搜索](im-search.md) 的参数、定义与测试。
2. 在领域仓复刻示例：固定输入行、假模型、原提示词，加一条与 connect 旧输出的对照测试。
3. 在本仓补一条说明，指向镜像路径与行字段，不写代码。
4. 删除 connect 的 `extract.rs`、两个示例与 quanttide-agent 依赖，检查 `cargo tree` 不再有 LLM 客户端。

## 验收判据

- 本仓依赖树没有 quanttide-agent，代码里不出现模型名与 API Key 变量。
- 搜索行字段齐全，能拼出与旧示例相同的逐行文本。
- 领域仓的提取测试用假模型通过，输出结构与旧实现一致。
- 删除示例后 connect 的 `cargo test` 与 `cargo clippy` 仍通过。

## 风险与待定

- 富文本消息的 `content` 是 JSON 字符串，拍平后仍是原文；消费侧按需解析，适配层不解释。
- 提取结果的稳定性取决于模型版本，规则仍以文档为准，不要把提取结果当规则源。
- 聊天数据外发涉及合规，脱敏责任在领域侧；若要求适配层先脱敏，需要另立需求。
- 领域仓是否接受 Rust 库依赖未定，读镜像是最低耦合的备选。
